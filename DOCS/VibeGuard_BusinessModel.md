# VibeGuard 사업모델 — FREE / PRO 2단계

> 취약 라이브러리를 탐지·버전 상향하고, 하위 호환을 회귀 테스트로 증명하는 VibeGuard의 요금제(플랜) 정의 문서.
> [PRD](./VibeGuard_PRD.md)의 **탐지(SCA) → 위험도 검증 → 최소 안전 버전 상향 → 설치·회귀 증명 → GitHub PR** 흐름을 기반으로,
> FREE는 탐지·버전 상향 PR "경험"에 집중하고, PRO는 **회귀 증명**을 더한다.

| 항목 | 내용 |
|---|---|
| 문서 버전 | **v2.0 (방향 전환: SAST→SCA, 회귀 증명 중심)** |
| 최종 수정 | 2026-09-10 |
| 상태 | 확정 (플랜 2단계 Freeze) |
| 관련 문서 | [VibeGuard_PRD.md](./VibeGuard_PRD.md) · [VibeGuard_방향전환.md](./VibeGuard_방향전환.md) |

> 플랜 구분은 방향 전환 문서의 **언어 지원 등급**(PRD §4.3)과 그대로 대응한다.
> - **기본 등급** = 모든 언어, 탐지 + 버전 상향 PR (**회귀 증명 없음**) → **FREE**
> - **검증 등급** = 테스트가 있는 Python 리포, + **회귀 통과 증명** → **PRO**

---

## 0. 한 줄 정의

- **FREE = Dependency Fix** — 취약 라이브러리 탐지 + 최소 안전 버전으로 상향한 PR을 경험해보는 기본형.
- **PRO = Verified Dependency Upgrade** — 여기에 **"올려도 안 깨진다"를 회귀 테스트로 증명**하는 신뢰형.

> 핵심: **FREE도 탐지와 버전 상향 PR을 제공한다.** 그래야 사용자가 VibeGuard의 핵심 기능을 직접 경험하고,
> PRO는 "기능을 잠근 유료 버전"이 아니라 **버전 상향의 신뢰성(하위 호환 증명)을 높여주는 플랜**이 된다.

### 발표용 한 문장

> VibeGuard는 무료 플랜에서 취약 라이브러리를 탐지하고 최소 안전 버전으로 올린 PR까지 제공하고,
> PRO 플랜에서는 여기에 리포의 기존 테스트를 패치 전후로 실행해
> **버전을 올려도 기존 기능이 깨지지 않음을 스스로 증명**하는 서비스를 제공합니다.

## 2. FREE — 의존성 보안 체험형 (기본 등급)

### 핵심 타겟
- 대학생 / 취준생 / 개인 개발자
- Vibe Coding 사용자 / 개인 프로젝트 개발자

### 핵심 가치
> "내가 쓰는 라이브러리 중 위험한 걸 찾아주고, 안전한 버전으로 올린 PR까지 만들어준다."

FREE는 **모든 언어에서 탐지 + 버전 상향 PR**을 제공한다. 다만 "올려도 안 깨지는지"는 증명하지 않는다.

### FREE Flow

```
GitHub Repository 연결
        ↓
매니페스트 스캔 (Trivy, 다국어)
        ↓
취약 라이브러리 발견
        ↓
CVE 기본 분석 → 안전 버전 확인
        ↓
매니페스트 버전 문자열 상향
        ↓
Auto PR 생성 (증명 없음)
```

즉 **탐지 → 버전 상향 → PR**까지 경험시킨다.

### FREE에서 회귀 증명을 하지 않는 이유

```
취약 라이브러리 발견 -> 버전 상향 -> GitHub PR
```

"안전한 버전을 알려주고 올려준다" 수준까지만 제공한다.
**"올려도 기존 기능이 안 깨지는가?"**를 증명하지는 않는다 — 이 증명을 PRO의 핵심 가치로 가져간다.
(회귀 증명은 리포에 테스트가 있어야 하고, 언어별 설치·실행 방식이 달라 Python 우선 지원이다.)

## 3. PRO — 검증된 버전 상향형 (검증 등급)

### 핵심 타겟
- 프리랜서 / 1인 개발 사업자 / SaaS 개발자
- 실제 서비스를 운영하는 개발자
- 보안이 중요한 개인·소규모 개발 환경

### 핵심 가치
> "AI가 올린 버전을 믿는 것이 아니라, 리포의 기존 테스트로 안 깨진다는 것을 증명한다."

### PRO Flow — 설치 + 회귀 증명이 들어간다

```
GitHub Repository 연결
        ↓
매니페스트 스캔 (Trivy)
        ↓
취약 라이브러리 발견
        ↓
Agent 2: NVD / OSV / GHSA 교차 검증
        ↓
최소 안전 버전 결정 (major 점프 회피)
        ↓
② 설치(패치 전) → ③ 테스트(pytest) → 통과 (기준선)
        ↓
매니페스트 버전 문자열 상향
        ↓
② 설치(패치 후) → ③ 테스트(pytest) → 통과 (안 깨졌다) [OK]
        ↓
   (깨지면 버전 후보 낮춰 최대 2회 재시도)
        ↓
   Auto PR (회귀 증거 포함)
        ↓
   GitHub PR
```

PRD의 **탐지 → 검증 → 설치·회귀 증명 → PR** 흐름을 그대로 반영한다.

## 4. PRO에서 가장 중요한 4가지 기능

### ① 회귀 기반 하위 호환 증명 (Regression Proof)
FREE와 PRO를 나누는 가장 강력한 기준.

| | 메시지 |
|---|---|
| FREE | "이 라이브러리에 취약점이 있습니다. 안전 버전으로 올린 PR입니다." |
| PRO | "취약점을 확인했고 → 올리기 전 기존 테스트가 통과했고 → 버전을 올렸고 → 올린 뒤에도 통과함을 확인했습니다." |

```
FREE:  취약점 → 버전 상향 → PR
PRO :  취약점 → 설치·테스트(전) → 버전 상향 → 설치·테스트(후) 통과 → PR
```

> 우리가 테스트로 증명하는 것은 "취약함"이 아니라 **하위 호환 유지**다.

### ② 최소 안전 버전 정밀 결정
Trivy는 안전 버전 후보 목록만 준다. 어디까지 올릴지(보안 vs 호환성)는 AI가 저울질한다. 예: `urllib3 1.24.1`의 안전 버전이 1.24.2 / 1.25.9 / 1.26.18 / 2.2.2 / 2.7.0으로 흩어져 있을 때, major 점프(2.x)를 피해 결정한다.

### ③ 회귀 실패 시 자동 재시도
패치 후 테스트가 깨지면 버전 후보를 낮춰 **최대 2회** 재시도한다(PRD §6.4, D11).

```
Maximum Retry = 2
```

2회 모두 실패 시:
```
Regression Blocked — Human Review Required
```

> 재시도 상한은 **2회로 확정**(방향 전환 D11 = PRD §6.4). 이전 문서의 "3회" 표기는 폐기됨.

### ④ 회귀 증거가 포함된 Auto PR
단순 PR이 아니라 "올려도 안 깨진다"를 증명하는 PR 본문:

```
VibeGuard 의존성 보안 패치
====================
Vulnerability   : CVE-2019-20477 (pyyaml)
Severity        : Critical
Version         : 5.1 -> 5.4  (major 점프 없음)
--------------------
회귀 테스트 (하위 호환)
   패치 전 : 24/24 통과 (기준선)
   패치 후 : 24/24 통과 (안 깨짐)
--------------------
Result
   [x] 안전 버전으로 상향
   [x] 기존 기능 유지 확인
```

PRD §6.5 PR 본문 템플릿(버전 변경 + 패치 전후 통과 로그)과 직접 연결된다.

## 5. 수익 모델 — 과금 가치

가격보다 **과금 가치**를 먼저 정의한다.

### FREE — Dependency Fix
```
탐지(다국어) + 최소 안전 버전 상향 + Auto PR (증명 없음)
```
사용자가 VibeGuard의 핵심 기능을 무료로 경험.

### PRO — Verified Dependency Upgrade
```
정밀 검증(NVD/OSV/GHSA) + 최소 안전 버전 결정
+ 설치·회귀 테스트(패치 전후) + 자동 재시도 + 회귀 증거 PR + 상세 리포트
```

> 돈을 내는 이유가 "취약점을 더 많이 찾기 위해서"가 아니라
> **"올린 버전이 기존 기능을 깨지 않는다는 것을 증명받기 위해서"**가 된다.

## 7. PRD와의 정합 / 후속 확인 사항

- 플랜 개념은 PRD의 파이프라인·기능을 재배치한 것이며, 상태머신(QUEUED→…→COMPLETED)과 Agent 1~4 구조는 그대로 유지된다.
- FREE는 파이프라인 중 **A1(탐지) → A2 일부(안전 버전) → 버전 상향 → A4(PR)**, 회귀 증명(설치·테스트)은 생략.
- PRO는 **A1→A2(정밀 검증)→A3(설치·회귀 테스트 패치 전후 + 재시도)→A4(회귀 증거 PR)** 전 구간.
- 재시도 상한은 **2회로 확정**(방향 전환 D11). 이전 3회 표기 불일치는 해소됨.
- 플랜 구분을 위해 향후 필요한 데이터 모델 변경(예: `users.plan`, 스캔별 플랜 스냅샷 등)은 Flyway 마이그레이션(`V2__…`)으로만 반영한다.
